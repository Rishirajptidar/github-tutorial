GIT :    virsion control system tool
         we can track changes made in the code.
         go back to see older version
         we can work in team without messing up each other's work.
Github : platform where we host our git repositories.
         store and share git repo or our projects.
         we can collaborate with other, track issues, review code, etc
Repository : just a project folder.
             contains code, documentaion and history of changes.
             can be shared locally or remotely.

---------------------------------------------------------------------------------------------

Special Points :
    * Git do not track empty folders.
      If we want git to track empty folders as well then we have to create a new file .gitkeep.
      this will be hidden and the folder will be tracked, it is used when we strictly want to
      preserve the core structure even with empty folders otherwise git will iignore those empty folders.
      we have head that points to the latest commit by default
      
---------------------------------------------------------------------------------------------

Flow :

working directory --->>> staging Area[Snapshot] --->>> Repository
(normal folder)            (git add .)          (git commit -m "message")

---------------------------------------------------------------------------------------------

File States : 

U : Untracked : files only in working directory.
M : Modified : ek commited file ko agr modify kiya he or uske bad commit nahi kiya.
Staged : staged in a single unit but not commited.
Commited : commit the staged unit.

---------------------------------------------------------------------------------------------

Logs : They store the whole process and allows you the time travel,
       They store the commit id, Author who commited and the date and time.
       git log : to get the detailed log report.
       git log --oneline : to get the short one line commit info only

---------------------------------------------------------------------------------------------

Git Ignore : when we want that some files should not be tracked by the git.
             They should not be staged, they should not be commited.
             we have things like env variables .env file, api secrates and we dont want to 
             track it or push it publically so we use git Ignore

             Create a folder .gitignore and write name of all the files or folders that we dont want to track,
             git will simply ignore them.

             git do not tracks the empty folders, but if you want any folder to be tracked just to maintain the
             structere of the code the we can add a simple .gitkeep file in it and now this folder will be tracked.

Branches and merges : in real world multiple people work on the same project, so they creat their own branch from the master branch.
           They do their task in that branch, and whenn complited they merge it with the main branch 

           the commit from which the branch is created it is called ancestor and it automatically inherit the before commits.
           the commit where the branch merge in the master branch is called merge commit.

           git branch : this is the command to list all the Branches.
           Branching: Allows for parallel development. New branches are created from the HEAD (the latest commit of the current branch).
           git switch branchname : this is the command to switch to any branch and create new branch.
           git switch -c new_branch_name :

           git merge branchname -m "message" : this is used to merge files in the master branch. 
           Merge Commits: Creating a merge commit is standard practice to finalize the integration of a feature branch into the master branch.
           


-----------------------------------------------------------------------------------------------------------------------

merge conflicts : this occurs when two branches modify same file or same line of code and merged to the master branch. now git is confused between which commit to give the piority
                  Cause      : Conflicts occur when Git cannot automatically reconcile differences between two branches (e.g., both branches modified the same line).
                  Resolution : You must manually edit the conflicting file to remove the conflict markers (e.g., <<<<, ====, >>>>) and choose the desired code version before committing the resolution.
